# Risk Register

| ID | Rischio | Severita | Stato | Mitigazione |
| --- | --- | --- | --- | --- |
| R-001 | `web/` non tracciata in Git | Alta | Aperto | Consolidare baseline e includere la web app nel controllo versione. |
| R-002 | H2 in memoria e `ddl-auto: update` | Alta | Mitigato parzialmente | PostgreSQL, Flyway e `ddl-auto: validate` introdotti per la web app; serve validazione su dati reali. |
| R-003 | Sessioni in memoria | Media | Mitigato | Sessioni backend persistite su database con token hashati, revoca logout e cleanup programmato. |
| R-004 | Account demo hardcoded | Media | Mitigato parzialmente | Seed super admin spostato su configurazione `dev/test` e disattivato in `prod`; resta da definire bootstrap produzione. |
| R-005 | H2 console esposta nella configurazione corrente | Media | Mitigato | H2 console disabilitata nella configurazione web corrente. |
| R-006 | API con `findAll()` non paginati | Media | Mitigato parzialmente | Prodotti, anagrafiche, movimenti, ordini, documenti, account e audit hanno paginazione e filtri server-side collegati ai controlli frontend; restano snapshot completi temporanei per dashboard e compatibilita UI. |
| R-007 | Frontend concentrato in `App.tsx` | Media | Mitigato parzialmente | Pagine, layout, navigazione, hook, componenti e client API di dominio sono separati; resta da distribuire lo stato applicativo per dominio. |
| R-008 | Dati `actor` e `role` inviati dal client | Alta | Mitigato | Magazzino, ordini e documenti derivano attore e ruolo dalla sessione backend. |
| R-009 | Documenti simulati confusi con documenti fiscali reali | Alta | Mitigato parzialmente | Disclaimer invariabile, snapshot azienda/cliente/IVA e nessuna dichiarazione di conformita fiscale; mancano integrazione SDI e validazione professionale. |
| R-010 | Codici ordine/documento basati su count | Media | Mitigato | Ordini con sequenza database e documenti con contatori atomici distinti per tipo ed esercizio, coperti da vincoli univoci e test concorrenti. |
| R-011 | Mancanza Docker e profili ambiente | Media | Mitigato | Stack prod-like containerizzato con PostgreSQL, backend e frontend Nginx; profili `dev`/`test`/`prod` separati e smoke test sullo stack reale. |
| R-012 | Mancanza CI | Media | Mitigato | Pipeline con hygiene repository, test backend, test e build frontend, stack Docker prod-like e quality gate. |
| R-013 | Nessun modello clienti/fornitori reale | Media | Mitigato parzialmente | Introdotte anagrafiche clienti/fornitori e collegamento ordini; restano validazioni fiscali e snapshot documentale. |
| R-014 | Concorrenza stock non gestita | Alta | Mitigato | Versione JPA su prodotti, operazione centralizzata di aggiustamento stock, risposta `409` sui conflitti e test su scarichi concorrenti. |
| R-015 | Errori difficili da correlare tra frontend e backend | Media | Mitigato | `X-Request-Id` propagato da frontend a backend, restituito nelle risposte, scritto nei log richiesta e salvato negli eventi audit. |
| R-016 | Brute force login gestito solo in memoria | Media | Mitigato | Tentativi e lockout sono persistiti nel backend; Nginx limita inoltre il login per IP, restituisce `429` tracciabile e viene verificato nello smoke test prod-like. |
| R-017 | Layout frontend vincolato a viewport desktop ampio | Media | Mitigato | Rimossa la larghezza minima globale; griglie, filtri, form e shell usano breakpoint progressivi, mentre lo scroll orizzontale resta confinato alle tabelle. |
| R-018 | Regressioni frontend rilevate solo manualmente | Media | Mitigato | Introdotti 32 test Vitest/React Testing Library e tre smoke test Playwright sullo stack reale, eseguiti dalla CI con diagnostica su errore. |
| R-019 | Saldi pagamento modificabili senza storico | Alta | Mitigato | Introdotto ledger immutabile per incassi e rimborsi, saldi vincolati a database, audit e idempotenza. |
| R-020 | Resi duplicati o reintegro magazzino prematuro | Alta | Mitigato | Quantita controllate sull'ordine, workflow esplicito e reintegro solo alla ricezione del reso approvato. |
| R-021 | Modifica incoerente della configurazione aziendale o della numerazione dopo l'emissione | Alta | Mitigato | Permesso esclusivo super admin, versione ottimistica, audit, snapshot immutabili e blocco di prefissi/padding dopo il primo documento dell'esercizio. |
| R-022 | Export molto estesi o contenuti interpretati dal foglio elettronico | Media | Mitigato parzialmente | Limite server-side di 10.000 righe, periodo massimo di cinque anni, Formula Injection neutralizzata, permesso e audit dedicati; per volumi superiori serviranno export asincroni/streaming e quote operative. |
| R-023 | IP client errato o limite login incoerente dietro proxy, NAT o piu repliche | Media | Aperto | Non fidarsi di header forwarding arbitrari; configurare proxy fidati, calibrare le soglie su NAT reali e introdurre un rate limiter condiviso prima di scalare Nginx orizzontalmente. |
| R-024 | Token browser leggibile da JavaScript in caso di XSS | Alta | Mitigato parzialmente | Token solo in memoria, mai in storage persistente, rotazione al rinnovo, scadenza assoluta/inattivita e risposte `no-store`; CSP same-origin in enforcement senza `unsafe-inline`/`unsafe-eval`, header browser e test Chromium riducono la superficie. Resta il rischio di codice same-origin o dipendenze compromesse. |
| R-025 | Endpoint operativi o dettagli Actuator esposti insieme alle API | Alta | Mitigato parzialmente | Profilo produzione con management port interna separata, esposizione limitata a `health` e `prometheus`, dettagli health nascosti, liveness/readiness distinte e controllo automatico sulla porta API. Resta necessaria una network policy nell'orchestratore reale. |
| R-026 | Segreti esposti in configurazioni container, file locali o storia Git | Alta | Mitigato parzialmente | Resolver fail-closed, file secret read-only, verifica `docker inspect`, template ignorati e Gitleaks sulla storia. Resta da integrare il secret manager remoto con identita workload, cifratura, audit e rotazione del provider scelto. |
| R-027 | Compromissione container con privilegi root o filesystem persistente scrivibile | Alta | Mitigato parzialmente | Processi non-root verificati, root filesystem read-only, `no-new-privileges`, capability eliminate e scritture confinate. Restano patching immagini, isolamento runtime, network policy e policy admission della piattaforma reale. |
| R-028 | Backup assente, corrotto o non ripristinabile durante un incidente | Alta | Mitigato parzialmente | Backup atomico giornaliero con checksum, lock, retention, controllo freschezza e restore drill settimanale isolato. Restano replica off-site, cifratura, immutabilita, alert esterni e prova di ripristino dalla copia remota nell'infrastruttura reale. |
| R-029 | Errori, degrado o attacchi non rilevati tempestivamente | Alta | Mitigato parzialmente | Log JSON correlati, metriche a cardinalita limitata, Prometheus prod-like e cinque regole alert verificati in CI. Restano collettore log centralizzato, Alertmanager con canale on-call, alta disponibilita e calibrazione soglie nell'ambiente reale. |
| R-030 | Drift tra immagini, migrazioni e runtime prod-like rilevato troppo tardi | Alta | Mitigato parzialmente | Runner unico eseguito su modifica e settimanalmente, build con `--pull`, verifica Flyway su PostgreSQL reale, diagnostica sempre acquisita e cleanup certificato. Restano indisponibilita del runner GitHub, registry esterni e differenze rispetto all'orchestratore di produzione reale. |
| R-031 | Accesso cross-tenant durante una futura evoluzione SaaS | Critica | Aperto, progetto definito | ADR 0005 e proposta multi-tenant richiedono sessione tenant-bound, repository scoped, foreign key composte, RLS forzata, ruolo runtime non owner e test PostgreSQL/browser con almeno due tenant. Il rischio resta aperto finche l'implementazione non e completata e verificata. |
| R-032 | Dati personali conservati senza finalita, retention o gestione dei diritti verificabile | Critica | Aperto, progetto definito | ADR 0006 richiede inventario, registro approvato, workflow interessati, policy versionate, legal hold, dry-run, quattro occhi, erasure ledger e restore coerente. Il rischio resta aperto fino a implementazione e approvazione professionale. |
| R-033 | Backup o repository applicativo presentato come conservazione elettronica a norma | Alta | Aperto, progetto definito | La proposta separa storage, backup e conservazione e richiede un provider validato, evidenze persistite, manuale, piano, responsabile ed exit test. Nessuna conservazione a norma e attualmente disponibile. |
| R-034 | Documento simulato presentato o trasmesso come fattura elettronica valida | Critica | Aperto, progetto definito | `FiscalDocument` resta simulato; il target usa un aggregato distinto, XML e schemi versionati, outbox, inbox ricevute, riconciliazione, sandbox, pilot e approvazione fiscale. Il rischio resta aperto fino al go-live verificato. |
| R-035 | Provisioning cliente parziale, duplicato o non riconciliato | Critica | Aperto, progetto definito | ADR 0007 richiede saga persistita, idempotency key, lock per target, retry dal primo step incompleto, compensazioni, inventario e gate prima di `ACTIVE`. Il rischio resta aperto fino a implementazione e pilot pooled/dedicato. |
| R-036 | Branding cliente introduce codice, XSS o rende inutilizzabili funzioni critiche | Alta | Aperto, progetto definito | Il target ammette solo design token e asset validati, rifiuta HTML/CSS/JavaScript arbitrari, mantiene fallback accessibili e verifica isolamento tenant. Nessun branding tenant e attualmente disponibile. |
| R-037 | Installazioni divergenti o compromesse durante release e migrazioni | Critica | Aperto, progetto definito | Release immutabili per digest, firma, SBOM, provenance, canali e coorti; preflight, auto-pause, compatibility matrix ed expand/contract sono obbligatori. Il rischio resta aperto finche fleet registry e rollout non sono implementati e provati. |
